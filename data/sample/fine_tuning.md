# Fine-Tuning Large Language Models

## Overview

Fine-tuning is the process of adapting a pre-trained language model to a specific task or domain by continuing training on a curated dataset. While pre-training gives the model broad language understanding, fine-tuning specializes it for particular use cases such as instruction following, code generation, domain-specific question answering, or style adaptation.

## Full Fine-Tuning

Full fine-tuning updates all parameters of the pre-trained model. For a 7B parameter model, this requires significant GPU memory (at least 28GB in fp32, 14GB in fp16) plus memory for optimizer states and gradients. Full fine-tuning provides the most flexibility but risks catastrophic forgetting, where the model loses general capabilities while learning the new task.

### Training Considerations

Learning rate selection is critical for fine-tuning. Rates that are too high cause catastrophic forgetting; rates too low result in insufficient adaptation. A common approach uses a learning rate 10-100x smaller than pre-training (e.g., 1e-5 to 5e-5) with a warmup period followed by cosine decay.

## Parameter-Efficient Fine-Tuning (PEFT)

PEFT methods adapt models by training only a small subset of parameters, dramatically reducing memory requirements and training time while preserving most of the model's pre-trained knowledge.

### LoRA (Low-Rank Adaptation)

LoRA freezes the pre-trained weights and injects trainable low-rank decomposition matrices into each layer. For a weight matrix W of dimensions d x k, LoRA adds a bypass: W' = W + BA, where B is d x r and A is r x k, with rank r typically between 4 and 64. This reduces trainable parameters by over 99% while achieving performance comparable to full fine-tuning.

Key hyperparameters include the rank r (higher = more expressive but more parameters), alpha (scaling factor, typically set to 2*r), and which modules to target (attention layers are most common, but including MLP layers can improve results).

### QLoRA

QLoRA combines LoRA with 4-bit quantization of the base model, enabling fine-tuning of a 65B parameter model on a single 48GB GPU. It introduces NF4 (Normal Float 4-bit) quantization, double quantization to reduce memory overhead of quantization constants, and paged optimizers to handle memory spikes.

### Prefix Tuning and Prompt Tuning

These methods prepend trainable continuous vectors (soft prompts) to the input or hidden states. Prompt tuning adds tokens only at the input layer, while prefix tuning adds them at every layer. These approaches are extremely parameter-efficient but may underperform LoRA on complex tasks.

### Adapters

Adapter layers are small bottleneck modules inserted between existing layers. Each adapter consists of a down-projection, non-linearity, and up-projection. Adapters add typically 1-5% additional parameters and can be efficiently shared and composed.

## Instruction Tuning

Instruction tuning fine-tunes a model on a dataset of (instruction, response) pairs to improve its ability to follow natural language instructions. Key datasets include Alpaca (52K examples generated by GPT), Dolly (15K human-written examples), and OpenAssistant (multi-turn conversation data).

### Chat Templates

Modern instruction-tuned models use specific chat templates to structure the conversation. Common formats include ChatML, Llama's [INST] format, and Mistral's format. Using the correct template is critical for optimal performance, as the model was trained to recognize these specific markers.

## RLHF and Alignment

### Reinforcement Learning from Human Feedback

RLHF trains a reward model on human preference data (which of two responses is better), then uses this reward model to fine-tune the language model via proximal policy optimization (PPO). This process aligns the model's outputs with human preferences for helpfulness, harmlessness, and honesty.

### Direct Preference Optimization (DPO)

DPO simplifies RLHF by directly optimizing the language model on preference pairs without training a separate reward model. It reframes the RLHF objective to show that the optimal policy can be extracted directly from preference data using a classification loss. DPO is simpler to implement, more stable to train, and has become increasingly popular.

## Evaluation of Fine-Tuned Models

### Benchmarks

Common benchmarks include MMLU (multi-task language understanding), HellaSwag (commonsense reasoning), HumanEval (code generation), TruthfulQA (factuality), and MT-Bench (multi-turn conversation quality). The Open LLM Leaderboard aggregates performance across multiple benchmarks.

### Evaluation Pitfalls

Benchmark contamination (training data overlapping with test sets) is a significant concern. Models may achieve high benchmark scores without genuine capability improvement. Evaluation should include task-specific metrics relevant to the deployment use case, human evaluation for subjective quality, and testing on held-out data from the target domain.

## Fine-Tuning vs RAG

Fine-tuning and RAG are complementary approaches. Fine-tuning is better for adapting model behavior (style, format, reasoning patterns) and encoding persistent knowledge. RAG is better for providing current, specific, or frequently changing information. In practice, the most effective systems often combine both: a fine-tuned model that is skilled at utilizing retrieved context, with a RAG pipeline providing relevant documents.
